MCP 개발 | 도구를 연결하는 서버

학습 목표
MCP 서버를 직접 한 파일로 만들고, 학습자 본인 MCP 설정 파일에 등록. 등록 후 자연어 요청 한 줄로 3 tool (get_logs · detect_anomaly · create_ticket)이 실제 호출되어 운영 사이클이 자동 동작하는지 본인 CLI에서 확인.

1MCP 3 역할 구조

MCP는 Host(AI 앱) · Client(연결 담당) · Server(도구 제공자) 3 역할 구조. 우리가 만드는 건 Server.

슬롯역할예시
tool실제 함수 | Python/Node 호출 가능get_logs(store, since)
resource정적/동적 데이터 | 매뉴얼 · 임계값pos_runbook.md
prompt안내 템플릿 | Claude Code 스킬과 동일 역할"이상 탐지 → 진단 → 티켓"

2pos-ops MCP 서버가 실제로 하는 일

본 강의용 pos-ops MCP server는 tool 슬롯에 3개 함수만 노출 (resource · prompt 슬롯은 비워둠).

tool이 함수가 하는 일
get_logs 매장 · 단말 · 상태별 거래 로그를 시간 역순으로 N건 조회
detect_anomaly 최근 N분 거래에서 이상 케이스 (POS_DOWN · PAYMENT_FAIL 등) 집계 + 가장 많이 발생한 이슈 선정
create_ticket 운영 티켓 생성 (제목 · 본문 · 우선순위 · 영향 매장 · 카테고리)

3회사 환경에서 로컬 RAG vs MCP · 스킬은 어디?

3.1 로컬 RAG vs MCP · 어느 케이스에 어느 쪽?

케이스권장
본인 노트 · 문서 검색 (보안 민감)로컬 RAG (Day 3 QMD)
회사 도구 (JIRA · Confluence · DB) AI 연결MCP 우선
둘 다 필요MCP 메인 + RAG는 매뉴얼 · 과거 티켓 검색 보조

3.2 스킬 vs MCP tool vs MCP prompt · 역할 분담

구분역할실행 주체
스킬 (.md)"AI에게 어떻게 행동할지" 안내AI 자체
MCP tool (함수)"실제 외부 시스템 실행"외부 프로세스 (Python · Node)
MCP prompt (안내)"AI에게 안내" (= 스킬을 MCP 안에 박은 것)AI 자체

가장 강력한 패턴 · MCP server 1개에 tool (실행) + resource (데이터) + prompt (안내) 3 슬롯 모두 활용 → 스킬을 MCP prompt 슬롯에 박아서 본인 회사 도구 · 매뉴얼 · 운영 흐름 한 패키지로 배포. 학습자 본인 CLI에 1줄 등록하면 자동 chain. 14차시에서 직접 해봅니다.

3실습 ② | resource 슬롯 채우기 (10분)

현재 비워둔 resource 슬롯에 회사 운영 매뉴얼·임계값·스키마를 노출. AI가 자동으로 컨텍스트로 가져감.

@mcp.resource("file:///path/to/manual.md")
def runbook() -> str:
    """POS 운영 매뉴얼 (Confluence export 또는 사내 .md)."""
    return open("manual.md").read()

→ rag-day3 QMD와 차이: QMD는 로컬 노트 검색용, MCP resource는 AI가 tool 호출 시 자동 참조하는 컨텍스트.

4실습 ③ | prompt 슬롯에 스킬 박기 (10분)

Claude Code 스킬과 동일 역할 | AI에게 "이렇게 행동해라" 안내 템플릿. MCP 1 패키지 안에 통합 배포:

@mcp.prompt()
def anomaly_triage() -> str:
    """이상 탐지 → 진단 → 티켓 5단계 흐름."""
    return """
    1. detect_anomaly(window_min=60)
    2. 임계 초과 시 매뉴얼 §섹션 검색
    3. 유사 과거 티켓 3건 조회
    4. create_ticket(P1~P3, body=매뉴얼 인용 + 사례)
    5. 알림 채널 전송
    """
