MCP 개발 | 도구를 연결하는 서버

학습 목표
MCP 서버를 직접 한 파일로 만들고, 학습자 본인 MCP 설정 파일에 등록. 등록 후 자연어 요청 한 줄로 3 tool (get_logs · detect_anomaly · create_ticket)이 실제 호출되어 운영 사이클이 자동 동작하는지 본인 CLI에서 확인.

1MCP 3 역할 구조

MCP는 Host(AI 앱) · Client(연결 담당) · Server(도구 제공자) 3 역할 구조. 우리가 만드는 건 Server.

슬롯역할예시
tool실제 함수 | Python/Node 호출 가능get_logs(store, since)
resource정적/동적 데이터 | 매뉴얼 · 임계값pos_runbook.md
prompt안내 템플릿 | Claude Code 스킬과 동일 역할"이상 탐지 → 진단 → 티켓"

2pos-ops MCP 서버가 실제로 하는 일

본 강의용 pos-ops MCP server는 tool 슬롯에 3개 함수만 노출 (resource · prompt 슬롯은 비워둠).

tool이 함수가 하는 일
get_logs 매장 · 단말 · 상태별 거래 로그를 시간 역순으로 N건 조회
detect_anomaly 최근 N분 거래에서 이상 케이스 (POS_DOWN · PAYMENT_FAIL 등) 집계 + 가장 많이 발생한 이슈 선정
create_ticket 운영 티켓 생성 (제목 · 본문 · 우선순위 · 영향 매장 · 카테고리)

스킬 = 로컬 디렉토리에 풀어둔 MCP 단위 · MCP = 표준 프로토콜로 묶은 스킬 패키지.

4실습 · 본인 업무 맞춤 hook 1개 추가

#훅 후보자연어 한 줄
1 티켓 생성 알림 (PostToolUse) "pos-ops create_ticket 호출 직후 내 알림 채널로 자동 알림 보내는 hook 추가해줘"
2 DB 위험 명령 가드 (PreToolUse) "POS DB tool 호출 시 WHERE 없는 UPDATE/DELETE 자동 차단 hook"
3 Jira 티켓 자동 코멘트 (PostToolUse) "tool 호출 결과 현재 처리 중인 Jira 티켓에 자동 코멘트 hook"
4 Confluence 매뉴얼 자동 첨부 (UserPromptSubmit) "'환불 처리' · '단말 다운' 키워드 감지 시 Confluence 해당 페이지 자동 컨텍스트 첨부 hook"
5 출근 brief (SessionStart) "세션 시작할 때마다 내 담당 Jira 미해결 티켓 + 어제 처리 요약 자동 brief hook"
6 Playwright E2E 자동 (PostToolUse) "git commit 직후 Playwright E2E 자동 실행 + 실패 시 알림 hook"
7 gstack 스킬 자동 호출 (PostToolUse) "tool 호출 후 gstack qa 또는 browse 스킬 자동 실행해서 결과 확인 hook"

→ Day 2에서 설치한 gstack 47 스킬 목록을 보면서 "어떤 작업을 hook으로 자동화하면 좋을지" 아이디어를 얻을 수 있습니다.

위 후보들은 pos-ops MCP뿐 아니라 본인이 등록해 둔 다른 MCP (Jira · Confluence · Playwright 등)에도 그대로 작동합니다. AI에게 자연어 한 줄만 던지면 hook 작성 · 등록 · 동작 확인까지 자동.

OpenCrab + 9단계 온톨로지 + 운영 모니터링

학습 목표

1OpenCrab MCP 설치

원본 repo (학술 layer 없는 깨끗한 베이스 · 로컬 SQLite + Chroma · 외부 DB 불필요): github.com/AlexAI-MCP/OpenCrab

자연어 요청 (Copilot CLI · 권장)

Python 3.10+ · Windows native는 chromadb 빌드 이슈 가능 → WSL 권장 · 데이터는 ./opencrab_data/ 로컬 보관.

2사내 문서 ingest + 검색

자연어 요청 (Copilot CLI · 권장)
"내 사내 문서 폴더 [경로]를 OpenCrab에 ingest하고 '환불 처리' 검색해서 매칭 문서 알려줘"

AI가 ontology_ingest · ontology_extract · ontology_query 자동 chain.

39단계 본인 도메인 ontology 모델링

본인 업무 도메인 1개 선택 (POS 운영 / Jira 티켓 / Confluence 매뉴얼 / 이메일 / 일정 등 무엇이든). 9 step:

step작업예시 (Jira 티켓 도메인)
1도메인 결정"운영 티켓 자동 분류"
2entity 후보 5~9개Ticket · Reporter · Assignee · Category · Status · Priority
3관계 후보 3~7개Reporter→creates→Ticket / Assignee→handles→Ticket / Ticket→has→Category
4한 줄 명세각 node/edge "이건 무엇" 한 줄
5YAML 작성OpenCrab ingest 형식
6ontology_ingest(yaml)로컬 instance
7ontology_query("...")자연어 → 그래프 traversal
8회사 도구 연동Jira ticket ID · Confluence page ID를 node 속성으로 연결
9MCP 통합14차시 MCP resource 슬롯에 ontology 노출 → AI 자동 참조

4HTML 대시보드 + 자연어 한 줄 chain

매장별 KPI · 시간대별 거래 · 이상 유형 분포 · 미해결 티켓 한눈에. → 대시보드 보기

자연어 요청 (Copilot CLI · 권장)
"POS_DOWN 강남역점 30분째. 매뉴얼 §3 조치 절차 인용하고 P1으로 티켓 만들어줘"
자동 chain (MCP + Hook + QMD + OpenCrab 합작):
  1. detect_anomaly(window_min=30, store="SEL-001") → top_issue=POS_DOWN
  2. qmd query "POS_DOWN 조치" → 매뉴얼 §3.1 5단계 인용
  3. ontology_query → 영향 entity·티켓·담당자 traversal
  4. PreToolUse guard_ticket → title 5자·P1 body 30자 검증
  5. create_ticket(title, body=매뉴얼 인용+사례, priority=P1)
  6. PostToolUse on_anomaly → 자동 알림
Day 4 산출물 · "Copilot CLI 한 줄 → 6단계 자동 chain". 탐지 (MCP) → 매뉴얼 검색 (QMD) → 의미 layer (OpenCrab) → 가드 (Hook) → 티켓 생성 (MCP) → 알림 (Hook). 외부 API 0건, 데이터 외부 유출 0건. AI Agent 인프라 모니터링 실시간 관제 한 사이클.
